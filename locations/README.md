# מיקומי סניפים

הקבצים `shufersal.json`, `ramilevi.json` ועוד **נוצרים אוטומטית** מחיפוש כתובות בשירות מפות
(`python -m collector.locate`). אין לערוך אותם ביד: ההרצה הבאה תדרוס את השינוי.

## איך מתקנים סניף ביד

לכל רשת יש קובץ תיקונים משלו: `<רשת>.manual.json` (למשל `ramilevi.manual.json`).
מוסיפים בו שורה לפי מספר הסניף (המספרים בדוגמה הם להמחשה בלבד). התיקון **גובר על החיפוש**: הסניף כבר לא יחופש,
והאתר יציג את הנקודה שכתבתם.

```json
{
 "006": {
  "lat": 31.7706,
  "lon": 35.3094,
  "city": "מעלה אדומים",
  "note": "הנקודה נלקחה ממפות גוגל, איתם 1"
 }
}
```

- `lat` ו-`lon` – קו רוחב וקו אורך, מספרים עם נקודה עשרונית (בגוגל מפות: לחיצה ימנית על המקום,
  ושני המספרים הראשונים שמופיעים).
- `city` – שם העיר (אפשר להשמיט; אז נשארת העיר שנמצאה בחיפוש).
- `note` – למה תוקן (אופציונלי, לזיכרון בלבד).
- `precision` – אפשר להשמיט. ברירת המחדל `address` (נקודה מדויקת). אפשר גם `street`, `city`.
- מספר הסניף עם או בלי אפסים מובילים ("006" או "6") – זה אותו סניף.
- שורות ששמן מתחיל בקו תחתון (`_help`) הן הערות ומדלגים עליהן.

מספרים מחוץ לישראל, או שורה בלי `lat`/`lon`, **נדחים עם הודעת שגיאה** שמציינת את הסניף
(כדי שטעות הקלדה לא תגיע למפה).

## מה בקבצי התוצאה
דרגת הדיוק (`precision`): `address` כתובת מדויקת, `street` רחוב בלבד, `store name` נקודת שם הרשת בעיר
(ייתכן סניף אחר), `city` מרכז העיר בלבד. שתי האחרונות הן ברמה גסה, ומי שרוצה לשפר סניף כזה
מוסיף לו תיקון ידני.
